## Problem Summary

You are given two strings, `str1` and `str2`, of lengths $n$ and $m$, respectively.

A string `word` of length $n + m - 1$ is defined to be generated by `str1` and `str2` if it satisfies the following conditions for each index $0 \le i \le n - 1$:
- If `str1[i] == 'T'`, the substring of `word` of size $m$ starting at index $i$ is **equal** to `str2`, i.e., `word[i .. (i + m - 1)] == str2`.
- If `str1[i] == 'F'`, the substring of `word` of size $m$ starting at index $i$ is **not equal** to `str2`, i.e., `word[i .. (i + m - 1)] != str2`.

Return the **lexicographically smallest** possible string that can be generated by `str1` and `str2`. If no valid string can be generated, return an empty string `""`.

---

### Examples

#### Example 1:
- **Input:** `str1 = "TFTF", str2 = "ab"`
- **Output:** `"ababa"`
- **Explanation:**
  The table below represents the string `"ababa"`:
  | Index | T/F | Substring of length $m$ |
  | :---: | :---: | :---: |
  | 0 | `'T'` | `"ab"` |
  | 1 | `'F'` | `"ba"` |
  | 2 | `'T'` | `"ab"` |
  | 3 | `'F'` | `"ba"` |

  The strings `"ababa"` and `"ababb"` can both be generated. We return `"ababa"` since it is lexicographically smaller.

#### Example 2:
- **Input:** `str1 = "TFTF", str2 = "abc"`
- **Output:** `""`
- **Explanation:**
  No string that satisfies the conditions can be generated due to contradictory character assignments.

#### Example 3:
- **Input:** `str1 = "F", str2 = "d"`
- **Output:** `"a"`
- **Explanation:**
  `word[0 .. 0] = "a" != "d"`, which satisfies the `'F'` condition while being lexicographically smallest.

---

### Constraints

- $1 \le n == \text{str1.length} \le 10^4$
- $1 \le m == \text{str2.length} \le 500$
- `str1` consists only of `'T'` or `'F'`.
- `str2` consists only of lowercase English characters.

---

## Algorithmic Approach

To find the lexicographically smallest string, we follow a greedy four-step approach:

1. **Phase 1: Enforce all `'T'` Constraints:**
   - Any `'T'` constraint mandates that `word[i + j] == str2[j]` for $0 \le j < m$.
   - If two different `'T'` windows demand contradictory characters at the same position in `word`, return `""` immediately.
   - All positions covered by a `'T'` are marked as **non-modifiable** (`modifiable = false`).

2. **Phase 2: Default Unconstrained Positions to `'a'`:**
   - Any position in `word` not locked by a `'T'` is initially filled with `'a'`, guaranteeing the smallest possible character prefix.

3. **Phase 3: Resolve Accidental `'F'` Matches:**
   - Scan each index $i$ where `str1[i] == 'F'`.
   - Check if `word[i .. i + m - 1]` currently equals `str2`.
   - If an accidental match occurs, we must break the equality while keeping the string lexicographically minimal.
   - We find the **rightmost modifiable position** in the range $[i, i + m - 1]$ and change it to `'b'`. (Since the cell was `'a'` and matched `str2`, changing it to `'b'` breaks the match).
   - If no modifiable position exists in that window (all positions were locked by `'T'`), it is impossible to satisfy the `'F'` constraint, so return `""`.
   - Mark the modified cell as non-modifiable.

4. **Phase 4: Final Verification:**
   - Verify all $n$ windows against `str1` to guarantee complete satisfaction of every constraint.

---

## Complexity Analysis

- **Time Complexity:** $\mathcal{O}(n \cdot m)$
  - Processing `'T'` constraints takes $\mathcal{O}(n \cdot m)$ operations.
  - Resolving `'F'` constraints checks windows of size $m$ at most $n$ times, taking $\mathcal{O}(n \cdot m)$ time.
  - Final verification takes $\mathcal{O}(n \cdot m)$ time.
  - Given $n \le 10^4$ and $m \le 500$, $n \cdot m \le 5 \times 10^6$, which comfortably executes in $\approx 10\text{ ms}$.
- **Auxiliary Space Complexity:** $\mathcal{O}(n + m)$
  - Array of length $n + m - 1$ to store characters and modifiable flags.
